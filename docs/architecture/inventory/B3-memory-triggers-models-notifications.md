- Behavior & invariants: append-only log; ≤280 UTF-8 bytes per line (`ENTRY_BYTES`); numbering per scope via `pos`; date is YYYY-MM-DD in the space's `settings.timeZone`; `forget` blanks text to "(forgotten at the user's request)", keeps number, bumps `epoch`, drops dependent tree blocks; a summary computed at an older epoch is discarded (`putSummary` returns false); `move` = append in target scope (new id, original date) + blank source (`moved=1`, text "(moved to another scope)"); tree blocks binary (size 2^k), blocks ≤16 memories summarized from raw lines, larger from two halves; max 20 named scopes, name ≤40 chars. Nap = pi task `optmem.nap`, `ownership: conversation`, `background: true`, phases next→summarize→retry (exp backoff `2^attempt*2000` ms), started by `startNap` if `nap_task` not running. Summaries need a model: `PIM_MEMORY_MODEL` else the noting conversation's agent model (`compressionModel`, `src/space/models.ts:470-480`). Prompt-cache rule: a conversation keeps the view it first saw; re-render only on forget/move, read-scope change, >1/8 (≥4) unseen memories, or a full view's worth of new ones.
- Computer required? no. Admin infra required? only a usable model for compression (Workers AI binding or provider); without it summaries stay missing and the view shows halves ("Not compressed yet: show its halves", `index.ts:145`).
- Authorization: owner-only via API (`/memory*`; guests reach only chat with their bot, `src/gateway.ts` header). Agent access computed per conversation by `#memoryAccess(agent)` (`src/pim.ts:1014`): majordomo reads `private` + `everyone` + every `agent-<id>`/named/orphan scope; other agents read own `agent-<id>` (and template-copy siblings), `everyone`, ticked named scopes (`agent.memoryScopes`); circles read `everyone` + ticked named scopes (`#circleMemory`, `src/pim.ts:1022`). `note` into a scope not in the caller's read set is refused. `create_memory_scope` majordomo-only; `share_memory_scope` is a gated action (approval) (`src/pim.ts:451`).

Resumable: **`optmem_meta.nap_task` points at a pi task**; if pi tasks are not migrated, delete `nap_task` so `startNap` creates a new one. Agent→scope links live in `pim_agents` (`memoryScope`, `memoryScopes`) and `pim_circles` (memoryScopes) — migrate together or readers vanish. The export (`exportData`) carries `memory.entries` (via `store.page`) and `scopes`, not the tree.

- Acceptance test: seed 40 memories across `private`, `everyone`, one named scope with one forgotten and one moved; export/import; verify `GET /memory` counts and `/memory/log?q=` identical, forgotten text blank, moved id mapping intact, `epoch` equal; run nap and confirm exactly one `optmem.nap` task, all ≤16-blocks summarized, a summary built before a post-import forget is rejected; verify an agent not ticked for the named scope cannot `recall` it.
