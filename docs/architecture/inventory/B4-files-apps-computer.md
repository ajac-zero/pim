## 1. Notes (Yjs live documents)

### Note document (Markdown note = artifact kind `markdown` + live Yjs doc)
- Sources: src/notes.ts:1-60 (design comment, schema), :47 COMPACT_AFTER=200, :52-64 tables, :154 checkpoint, :196 write, :287 #open, :`#updated` :322-325, `#compact` :341; src/extensions/notes.ts; src/space/sockets.ts:77,93-130,256-300,344-353; src/space/routes.ts:946-962 (POST /notes), :976-1005; docs/apps.md "## Notes".
- Canonical storage: **Two layers.** (a) The version history is an ordinary artifact (`pim_artifacts` kind=`markdown`, `pim_artifact_versions`, main file `README.md` in `pim_artifact_files` → R2 `ARTIFACTS:<owner>/<sha256>`). (b) The live truth is a Yjs doc: `pim_note_updates(seq AUTOINCREMENT, artifact, data BLOB)` (binary Yjs updates, compacted to ONE `Y.encodeStateAsUpdate` row after >200 rows) and `pim_notes(artifact PK, base INTEGER version the text was last saved as/adopted from, dirty INTEGER)`. Shared text name `"markdown"` (`NOTE_TEXT`, notes.ts:45). In-memory only: `#live` docs, per-note promise queues, awareness map (peer cursors). ID minted: `crypto.randomUUID()` in `POST /notes` (routes.ts:956) or memoized in tool `note_create` (extensions/notes.ts:96).
- Behavior & invariants: Live text is the truth; versions are checkpoints: person pause (client sends message type 2 ~30s after last keystroke), last editor leaves (`left` → `checkpoint`, notes.ts:146-150), before and after every agent change, before export (`checkpointAll`, reports.ts:355), on restore. Agent edits are find/replace applied to LIVE text (exactly-once match, else whole text replaced by the checked result); `append` adds on own line; `content` requires `baseVersion==latest` else 409. All ops per note serialized by `#queue`. A version made another way (older client's `POST /artifacts/:id/versions`, import) is adopted into live text the next time `#current` runs (base != latest). Yjs sync + awareness use y-websocket numbering (0 sync, 1 awareness, 2 CHECKPOINT = Pim-specific); server→client JSON notices `{type:"version"|"error"}`. Max message 2,000,000 bytes → close 1009. Delete closes sockets 4004 and `forget()`s rows. `dirty` persists, so a space that slept and wakes resumes an unsaved state. Undo is per-editor (client-side).
- Computer required? no. Admin infra required? no (needs only the space's DO storage + WebSocket hibernation). Admin can disable the built-in app (`disabled_builtin_apps` in Gallery; `POST /notes` → 403 while off; existing notes remain usable).
- Authorization: `/api/notes/live` is an ordinary authenticated API path (gateway admit: API token OR signed-in session; `?token=` accepted for WebSockets) and only for the caller's own space; there is NO cross-user note collaboration (notes can be shared/published as ordinary read-only artifacts, but `guestArtifact` serves the latest version only, not the live doc). Socket opens only if `artifacts.get(note).kind==="markdown"` else close 4004 (sockets.ts:114-122). Unlike `/computer/screen` there is no `viaSession` requirement (gateway.ts:646-655 [V]: `viaSession` is required only for `/computer/screen` and `/computer/displays*`).
- Migration/export-import: Export = ordinary artifact export (versions + files); live doc is NOT exported separately; `checkpointAll()` first so the latest text is a version. Platform import must (1) import artifact+versions+files, (2) either import `pim_note_updates` rows verbatim (Yjs updates are mergeable; concatenate in `seq` order and `Y.mergeUpdates`) plus `pim_notes` base/dirty, or (3) drop them and let `#open` rebuild a fresh doc from the latest version (loses CRDT history and open cursors; clients that hold local Yjs state with old client ids would duplicate text on reconnect — "a new doc made from the text would show it twice" per the file comment). Recommend (2) or force clients to reload with empty local state. No blobs beyond artifact files.
- Public ID/URL compatibility: note id = artifact id (`/artifacts/<uuid>`, `/chat/<id>?artifact=<id>&v=<n>`, `artifact://<id>` message links); socket `/api/notes/live?note=<uuid>`; `/api/notes` POST.
- Explicit settings/overrides to preserve: builtin app `notes` on/off (Gallery `disabled_builtin_apps`); per-note `pim_notes.base/dirty`; version `source` (agent|person|restore) and `restored_from`; `call_id` idempotency of agent writes.
- Dependencies (incl. cross-conversation coupling): depends on ArtifactStore (versions, limits `artifactVersions`, `artifactBytes`, space `storageBytes`); a note's live doc counts toward storage as DB size. A note records `session` = originating chat's INTERNAL session id (null for POST /notes); deleting the chat doesn't delete the note. Agents in any chat share notes (`note_list`, `note_show`): cross-conversation by design. Built-in skill `notes` (extensions/notes.ts:34-85) injected in every agent prompt.
- Acceptance test: Open two WebSocket editors on one note; type in A; B receives the update; agent `note_edit` with `edits` while A has typed elsewhere: both texts present; pause→ version `source:person`; close last editor → version; restart/evict the space (or reload DB) → reconnecting editor syncs without doubling text; export→import into the new stack and confirm identical `markdown` text and version list; `POST /notes` with notes disabled → 403.
- Uncertainty: [V] the web client holds the Yjs doc in memory only: `web/src/lib/note-live.ts:39` `new Y.Doc()`; no y-indexeddb dependency in `web/package.json` and no IndexedDB use in `web/src` except `saved-queries.ts` (grep) — so item (3) (drop the live rows) risks no stale-client duplication across a full page reload, but an already-open editor with live local state would still duplicate; [U] whether a doc kept in a background tab survives the cutover. Whether `/notes/live` is blocked for guest accounts (UNVERIFIED; gateway guest filter `guestRequest`).

## 10. Cross-cutting compatibility risks found (for the main inventory)
1. **Corrected (see §0.1):** what depends on the personal computer is exactly: `/workspace` files (incl. uploads saved as files, generated images, downloads, browser screenshots), file/shell/canvas tools, hosted-app release copies, backends and data, the agents' Chrome, the desktop/displays, computer-hosted triggers, and the legacy-file move. Chat image attachments, kept images/video, apps and every version, notes (Yjs), bridge data, sharing, publishing and the Gallery live in DO SQLite + R2 and work with no computer paired. A replacement computer/media service must offer the same `/workspace` + WebSocket protocol, or `/workspace` bytes must be copied (tar + per-file sha256).
2. Polymorphic keys in `pim_artifact_data/grants.artifact` (`<uuid>`, `<owner>/<uuid>`, `gallery/<pa_id>`) — importer must preserve them verbatim.
3. R2 key namespaces share `<owner>/` prefix across images (`<owner>/<uuid>`), legacy files (`<owner>/files/<id>`) and skills (`<owner>/skills/<sha>`) in BLOBS; `ImageStore.deleteAll()` and `any()` operate on the whole prefix. `ARTIFACTS` uses `<owner>/<sha256>`. A sha256 key could not collide with a UUID or `files/`/`skills/` prefixes.
4. Gallery rows point into authors' blob namespaces; recipients' code reads them directly from R2.
5. Chat transcripts (pi-durable) embed `/api/images/<id>`, `/workspace/...`, `artifact id+version+sha256`, `[Files you changed since your last turn]` — public-contract strings.
6. The per-chat `session` columns (`pim_artifacts.session`, `pim_images.session`, `pim_file_seen.session`) and displayd leases use the INTERNAL session id, not the public id (`pim_session_ids`): import must remap consistently.
7. Five different things are easily conflated: (a) the **personal computer** (`pim-computer`; files, shell, app backends, Chrome, desktop), (b) the **coding sandbox / remote coding service** (`src/coding/**`, sandbox-manager, hostopsd; B5), (c) the **hosted-app runtime** (a process the personal computer starts; not a separate service), (d) **Cloudflare Browser Run** (not used by product code; the `BROWSER` binding is test-only, grep `src/` found none), (e) the **computer host** (`pim-host`, makes managed computers). Each has its own code path.
8. Account erasure sequence (`deleteEverything`, `src/space/reports.ts:431-455` [V]): images→artifact files→quit browser→remove managed machine→wipe DO→mark erased; `remainingData` reports "images" and "app files" if any R2 object remains under the owner prefix — new stack needs an equivalent erasure+verification (`remainingData`) over Postgres rows, S3 prefixes, and the managed computer.
9. Export (`reports.ts:355-397`) is not import-complete: omits live Yjs rows, hosted data folders, legacy file content, credentials, grants of others' apps (partially), and caps inline file contents at 32,000,000 bytes.
