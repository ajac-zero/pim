## 0. Summary of the findings that matter most for the re-architecture

1. **The product is one Worker (`src/index.ts:16-20`, `export default { fetch }`, no other handler) plus 9 Durable Object classes** (`wrangler.jsonc:25-40` [V]). All durable state is DO SQLite plus DO key/value (the `Pim` DO's KV holds `agents`-library state such as MCP OAuth tokens and Lifecycle counters, §3.1; `CodingThreadDO` and the two Container classes use KV too, §3.2), plus two R2 buckets and one KV namespace (`wrangler.jsonc:67,73`). There is no D1, no Queue, no Workflow, no cron trigger, no service binding, no Analytics Engine, no Browser Run binding in production config.
2. **Cloudflare-only features the code genuinely depends on**: DO addressing by name (`getByName`) as the single-writer/fence primitive; DO alarms; hibernating WebSockets with tags; `ctx.storage.transactionSync` / `sync()` / `deleteAll()`; the `ASSETS` fetcher with `run_worker_first`; `CF-Connecting-IP`; the `ratelimits` bindings; `CF_VERSION_METADATA.timestamp` (first-admin claim window); Workers Logs (as the place the admin finds the setup link); R2 and KV; Workers AI (optional); Containers (optional).
3. **A non-Cloudflare runtime profile already exists**: `PIM_RUNTIME=celld` (`src/runtime.ts`) plus `deploy/celld/` (Caddy ingress with `X-Pim-Ingress-Secret` / `X-Pim-Client-IP`, Directory-based rate limiter, no claim window). It is the closest existing precedent for "Gate behind a proxy"; its Gate-side semantics (trusted-ingress, claim by log link, DO-counted limiter) can be lifted as-is. **Caveat [V]:** the committed celld profile (`deploy/celld/wrangler.jsonc:34-47`) binds only 4 DO classes (`Pim, Auth, Directory, Gallery`) and omits `CodingSchedulerDO`, `CodingThreadDO`, `HostOps`, `WorkspaceContainer`, `WorkspaceCatalog` and `containers`, although `src/index.ts:3-9,22` exports them and `wrangler.jsonc` binds them; see §1 row 10a. Coding threads and host ops are therefore not wired on celld at this SHA.
4. **Normal chat needs no coding infra, no computer, no Workers AI, no R2 for text-only use.** The one hard minimum is a **model provider** (admin-added or person-added OpenAI-compatible server, or a person's ChatGPT plan, or Workers AI) and `PIM_PUBLIC_URL`. Details in §6.
5. **Secrets are stored mostly in clear in DO storage**; only connector sign-ins (`APP_CREDENTIALS_KEY`; mandatory only for Gmail/Drive, optional for Spotify/GitHub), the Gitea connection and the coding vault are sealed. The Directory's random `cookie_key` is the HMAC key of the sign-in cookies *and* the HKDF input for 4 derived keys (§2.3). Losing/rotating it silently breaks several things (§3.2).
6. **No import exists**: `docs/instance.md:151` ("Import of an export is not built"); the per-person export (`GET /api/export`) deliberately omits credentials. The only reusable backup/migration facility is celld's cold-backup of the whole bucket (`docs/celld.md:202-206`) and the `exportData()` JSON shape.

## 5. Edge assumptions the code silently relies on

### 5.1 Request routing & hostnames
- Order of decisions in `serve` [V] (`src/gateway.ts:522-547`): `admitIngress` (`:523-525`) → request **origin** equals `PIM_CONTENT_ORIGIN` ⇒ public-artifact handler with the `public` limiter (`:527-531`) → host matches an apps-origin subdomain ⇒ hosted-app handler (`:532-534`) → `/health` and `/api/themes[.css]` are answered **before** the public-URL check, so they work even with `PIM_PUBLIC_URL` unset (`:535-537`) → no `PIM_PUBLIC_URL` ⇒ 503 `{missing}` (`:540-545`) → origin ≠ public URL ⇒ 421 (`:547`). Cloudflare's asset layer serves **paths not in `run_worker_first`** without the Worker (platform behavior, [U] in this repo); Gate must replicate that split (`wrangler.jsonc:17`; preview uses `true`; `/artifact-runtime/*`, `/pim-computer.ts`, `/displayd.tar.gz` are assets outside the list, §1 row 17). The web app's service worker keeps its own list, which must include `/hosted/*` when apps-origin is used (`docs/instance.md:131`, `web/public/sw.js`).
- Path map on the public origin [V, `src/gateway.ts:535-610`]: `/health`, `/api/themes[.css]`, `/api/diagram`, `/install.sh` (`:550-553`), `/auth/*` and `/oauth/*` (rate-limited non-GET, `:555-561`), `/mcp`, `/.well-known/*` (`serveOAuth`, `:563-565`), `/auth/authorize` + `/auth/connections` (`:567-575`), `/authorize` (asset page with frame-deny, `:579-587`), `/images/*`, `/app-pages/*`, `/hosted/*`, `/api/shared/*`, `/api/bots/*`, `/shared/*` (asset page, noindex), `/mcp/*` (connector callbacks/events/client via `serveApp`, `:605-608`), `/api/*` (`:610-655`); everything else is `ASSETS.fetch`. `/p/pa_<16 hex>` and `/artifact-runtime/*` are served by the Worker **only on the content origin** (`src/accounts.ts:89-97`); on the public origin `/p/*` falls to `ASSETS` (`:610`). `/b/<id>` is an app page (SPA asset) for a bot link (`src/accounts.ts:211`, `:113` id `b_<16 hex>`).
- `/api/<path>` WebSockets only at `/api/ws`, `/api/browser/live`, `/api/computer/screen`, note-live (`src/gateway.ts:646-648`); a non-WS request to those gets 426, a WS upgrade elsewhere 404. `/api/computer/connect`, `/api/computer-host/sync`, the git broker, model gateway and host-ops agent routes are answered **before** `admit()` with their own tokens (`:614-621`).

### 5.2 Client IP / geolocation
- Address = `CF-Connecting-IP` (or `"unknown"` if missing, `src/runtime.ts:140`). It feeds: auth rate limit, public rate limit, `PIM_REGISTRATIONS_PER_ADDRESS` (`registrations` table), hostops enrollment attempts. IPv6 is normalised to /64 by `clientAddress` (`src/runtime.ts:95-111`), IPv4-mapped IPv6 → IPv4. **Without a trusted proxy header, all clients behind one NAT/proxy collapse into one bucket**; Gate must derive a trusted client IP (celld: `X-Pim-Client-IP` + `X-Pim-Ingress-Secret`, `src/runtime.ts:25-27,133-152` [V]; the secret is compared in constant time (`:114-120`); both headers and any client `cf-connecting-ip` are stripped). No geolocation used.

### 5.3 CORS / origin / CSRF
- `Access-Control-Allow-Origin: *` on API and public routes (`src/gateway.ts:92`) with `Authorization, Content-Type` allowed; the session-cookie protection is the `fromAnotherSite` check: write methods and WebSockets must carry `Origin` equal to the request's own origin, GET/HEAD without `Origin` allowed (`src/auth/index.ts:230-237`, enforced for the API at `src/gateway.ts:151`, for `/auth/*` at `src/auth/index.ts:266` and for registration `src/accounts.ts:315,339`); API tokens skip it [V]. A reverse proxy that rewrites `Host`/scheme breaks this.
- `givenToken` (`src/gateway.ts:108-112`) takes `Authorization: Bearer …` **or, whenever no Bearer header is present, the `?token=` query parameter on any `/api` request** (the comment says for WebSockets, but the code does not restrict it) → tokens in access logs; Gate logging must redact [V].
- App pages: CSP sandbox for apps; `/authorize` is `frame-ancestors 'none'` + `X-Frame-Options: DENY`; public pages `referrer-policy: no-referrer`, `X-Robots-Tag: noindex`.

### 5.4 Cookies & WebAuthn
- Cookies: `__Host-pim-session` (30 days), `__Host-pim-challenge` (5 min), `__Host-pim-oauth`; `Path=/; Secure; HttpOnly; SameSite=Strict|Lax` (`src/auth/index.ts:75-81,186-188`). `__Host-` **requires HTTPS and no Domain** → no plain-HTTP self-host (even on localhost in preview they rely on Chrome's localhost-secure exemption — UNVERIFIED for Firefox/Safari).
- Hosted-app cookie is named `__pim_app` (`src/hosted.ts:50`; the first pass wrongly said `pim_app_session`) and uses `SameSite=Lax`, `Secure` only if apps origin is https (`src/gateway.ts:383`).
- WebAuthn rp id = **`new URL(request.url).hostname`** and origin = request origin (`src/auth/index.ts:267-268`), *not* `PIM_PUBLIC_URL` (but gateway has already 421'd any other origin). Passkeys are therefore bound to the public hostname forever; moving hostnames invalidates every passkey (`docs/instance.md:129`). Recovery codes survive. `userVerification: required` (`src/auth/index.ts:302,371`). rpId on an IP address does not work.
- Sessions are checked against the person's Auth object on every request (`currentSession`), not just cookie validity.

### 5.5 WebSocket hibernation
- `Pim` is an `Agent` with hibernating sockets; connection state (watched session, tags `computer`, `browser`, `screen`) lives in WS attachments and is **restored after wake** (`pim.do_start` event reports `watches` restored, `src/pim.ts:1196`, `docs/instance.md:109`). Computer pings are answered by `setWebSocketAutoResponse` without waking. After eviction the in-memory trace context, `ConnectionState`, caches and in-flight model streams are gone; runs resume by Lifecycle job. Live must either keep actors resident or re-implement resume-from-storage + socket reattachment.
- Close codes in use [V]: 4003 suspended (`src/pim.ts:2002`), 4010 deleted (`src/space/reports.ts:433`; also `WATCH_LOST` for a lost watch, `src/space/sockets.ts:28,517`), 4000 desktop/window/computer-connection changed (`src/space/sockets.ts:195,246,415`).
