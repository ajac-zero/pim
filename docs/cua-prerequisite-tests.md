### The Worker prerequisite lane

`vitest.cua-prerequisite.config.ts` names exactly the two files. Apart from its file list and messages, it is the Cua stand-in lane's configuration (`docs/cua-standin-lane.md`):

- **Serial.** One file at a time (`fileParallelism: false`), and each file's tests in order, as none is `concurrent`.
- **No Chrome.** The Worker has no Browser Run binding (`browserRendering`), so there is no `BROWSER`. The setup file `test/standin-lane.ts` is reused unchanged: it fails every file before its tests run if a `BROWSER` binding appears. Its message names the stand-in lane.
- **No live mode or remote bindings.** `PIM_LIVE` set at all stops the configuration before anything runs, and `remoteBindings` is off.
- **Files checked first.** Loading the configuration reads both files and refuses to run if either names `testBrowser`, `pairTestComputer`, `BROWSER`, `browserRendering`, `PIM_LIVE` or `test/live/`. Neither does.
- **The same Worker.** `test/worker.ts` with `wrangler.jsonc`, `testBindings` from `vitest.bindings.ts` (test values, no real credentials), and the preview's `PREVIEW_PIM` object as in the stand-in lane, which neither file uses.

The nine-file stand-in lane (`vitest.cua-standin.config.ts`) and its files are unchanged.

**The binder's crash tests now settle what they start.** Two tests modelled a process that dies while its call is out with a `send` whose promise never settled, which left a dispatch pending past its test. Each now holds the reply in a gate the test owns. After every original assertion has run (the restart takes the dispatch as `unknown`, sends nothing more, and latches the run), the test settles the gate as the dead process would see it:

1. It cuts off the dead process's storage (`disk.fail = "before"`), since nothing a dead process does is stored.
2. It answers the old call with a known outcome, the case most likely to wrongly settle it.
3. It waits for that dispatch to finish.

It then checks that the stored document didn't change, that the restarted binder still has the call `unknown` (and, in the first test, its neighbour `closed`), and that nothing was sent. No assertion was removed or weakened. No other prerequisite test leaves a promise pending: the observation manager's crash test settles through its own `crash()`.

### The host tests, and why the Cua endpoint tests have their own file

`session.test.ts` tests the bridge's sessions and the desktop endpoint. The child bootstrap added its "starting the Cua computer" tests there, but some of the file's other tests start real processes:

- A killed socket holder (`spawnProcess`, "leaves a file, a link, a socket left behind…").
- A Node script in place of pim-computer ("passes on only what a real child writes…").
- `openssl`, and the bridge and endpoint programs with the real `pim-computer.ts` ("the bridge and the endpoint as programs").

A name filter (`--test-name-pattern`) would still load the file and report the other tests as skipped, which can't be told from unexpected skips. So the "starting the Cua computer" block was moved, character for character, to `computer/cua-host/test/cua-endpoint.test.ts`, with copies of the helpers it uses (`HELLO`, the program paths, `tick`, `until`, the `afterEach` cleanups, `place`, `FakeChild`, `endpoint`, `events`, `settle`), also unchanged. Checked by counting: the 8 tests and 87 `assert.` calls of the block are all in the new file, `session.test.ts` keeps its other 21 tests, and the two files together hold the original 29 tests and 190 `assert.` calls. `session.test.ts` lost only the block, the now-unused imports and `CUA_COMPUTER`, and the sentence of its header about the Cua credential.

**What `cua-endpoint.test.ts` can reach, by reading it and what it imports:**

- **No child process.** It imports no `child_process` function. Every `createDesktopEndpoint` in it is given a `spawn`: either the `endpoint` helper's, which records the call and returns a `FakeChild`, or one that throws or fails the test. A `FakeChild`'s `kill` only records the signal. `desktop.ts` uses `child_process.spawn` only as the default for a missing `spawn`.
- **No credential.** Every endpoint given a `cua` child is also given the stand-in `credentialFiles`, and the one with no `cua` gets a stand-in that fails if touched. `NODE_CREDENTIAL_FILES` is never used, and `/etc/pim-cua/spacesd.token` is only a name.
- **Top level and hooks.** The top level defines constants and functions, and registers one `afterEach`, which removes each test's folder and closes its endpoint after ending its `FakeChild`ren.
- **Imports.** The imported modules (`desktop.ts`, `session.ts`, `host.ts`, `cua-credential.ts`, `../cua-bridge.ts`, `../native-outcome.ts`) define constants, classes and functions. `host.ts` also makes one in-memory `net.BlockList`, and imports `ws`. `desktop.ts` runs its `main` only when it is the program Node was started with: it reads the real path of `process.argv[1]` (here the test file) to check, and doesn't match.

**Its effects, which are expected:**

- One folder per test under `os.tmpdir()` (`cua-desk-*`), holding a stand-in browser script that is written (mode 0700) and never run. One test also writes a `writable.ts` of mode 0666 there.
- A Unix socket in that folder that the endpoint listens on and the test connects to, with Node's timers for waits of at most 5 s.
- All of it removed after each test.

`cua-computer.test.ts` opens no descriptor, file, process or socket: its descriptor, `fetch` and `serve` are stand-ins. Importing `cua-computer.ts` and `pim-computer.ts` reads the real path of `process.argv[1]` for their `main` checks, and nothing else. `viewer-launch-manager.test.ts` imports only `viewer-lifetime.ts` at run time, uses hand-turned clocks, and makes no file, socket or process.

## How to run it, once authorized

Each step is a separate run with its own deadline, from the repository's root, and stops at the first failure. Nothing below inspects, signals or cleans up any process other than the one the step itself starts. If a deadline is reached, `timeout` ends the command it started. What that leaves behind, such as a workerd that Vitest started, is reported, not looked for or killed: that needs its own permission.

**0. Preconditions.** These read files and print versions only.

```sh
git rev-parse HEAD                      # the prepared commit
git status --porcelain                  # must be empty
node --version                          # at least v22.18.0
test -d computer/cua-host/node_modules/ws || echo "the host package isn't installed: stop, installing needs its own authorization"
```

**1. The Worker prerequisite lane.** Its deadline is 300 s. The stand-in lane's 144 tests took 131 s; these 30 need no Durable Object.

```sh
RUN_TMP=$(mktemp -d "${TMPDIR:-/tmp}/pim-prereq-worker-XXXXXX")
TMPDIR="$RUN_TMP" timeout --signal=TERM --kill-after=15s 300s node_modules/.bin/vitest run --config vitest.cua-prerequisite.config.ts
```

It passes when the exit status is 0 and Vitest reports 2 files and 30 tests passed, none skipped or todo.

**2–4. The host files.** Each runs as its own Node process, directly and not through `node --test`, so no test runner starts another process. Deadlines are 120 s for `cua-endpoint.test.ts` and 60 s for the other two.

```sh
RUN_TMP=$(mktemp -d "${TMPDIR:-/tmp}/pim-prereq-host-XXXXXX")
TMPDIR="$RUN_TMP" timeout --signal=TERM --kill-after=10s 120s node computer/cua-host/test/cua-endpoint.test.ts
TMPDIR="$RUN_TMP" timeout --signal=TERM --kill-after=10s 60s node computer/cua-host/test/cua-computer.test.ts
TMPDIR="$RUN_TMP" timeout --signal=TERM --kill-after=10s 60s node computer/cua-host/test/viewer-launch-manager.test.ts
```

Each passes when its exit status is 0 and its summary says `tests` equal to its count above, `pass` the same, and `fail`, `skipped`, `todo` and `cancelled` 0.

**After each step: the owned cleanup checks.** These cover only what the step was given.

```sh
find "$RUN_TMP" -mindepth 1 -print | head   # must print nothing: every test removed its folder and socket
rmdir "$RUN_TMP"                            # fails, and is reported, if anything was left
git status --porcelain                      # must still be empty
```

**5. Types, as separate runs, if authorized:**

- `timeout 120s node_modules/.bin/tsc --noEmit` for `src/` and `test/`.
- `timeout 120s node_modules/.bin/tsc --noEmit -p computer/cua-host/tsconfig.json` for the host. This needs the host package installed, for `@types/node` and `ws`.
